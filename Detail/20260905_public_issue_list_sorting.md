# 2026-09-05 公開雑誌号一覧の並び順・ヘッダーソート修正

## 対象

- `indexindex/issues.php?magazine_id=...` の雑誌別号一覧
- 確認例：`magazine_id=133`（月刊コミックフラッパー）

## 調査結果

- デフォルト表示は発行年、号数、補助日付の昇順を意図していた。
- ただし `issue_no` と `publication_month` が未入力の「2026年6月号」などは、`issue_label` の先頭の数字（2026）を号数として扱っていた。
- 同年の各号が同じ号数キーになり、その後の発売日・発行日によって並ぶため、1月号、2月号、6月号、7月号…という号数順にならない場合があった。
- 雑誌別号一覧の「号」「発行年」「目次件数」ヘッダーには、他の公開一覧にある並び替えリンクがなかった。
- 雑誌別ページのURL生成では `sort` / `direction` が保持されず、ページ移動時に並び替え条件が失われる状態だった。

## 修正内容

- 人物・作品の公開ページで使用している補完方法に準拠し、`issue_label` が「YYYY年M月号」形式なら年と月の間の数字を月号として取得するようにした。
- 号数キーの優先順位を次のようにした。
  1. `issue_no` の先頭数値
  2. `publication_month`
  3. `issue_label` の「年」と「月」の間の数値
  4. `issue_label` 先頭の数値（従来の最終フォールバック）
- デフォルトを「号の昇順」にし、現在の並び順を `▲` / `▼` で表示するようにした。
- 「号」「発行年」「目次件数」の各ヘッダーをクリックすると昇順・降順を切り替えられるようにした。
- ページネーションとページ番号移動でも `sort` / `direction` を維持するようにした。
- 許可リスト方式で並び替え項目と方向を検証し、任意のSQL文字列が入らないようにしている。

## 想定される表示順

デフォルトでは、同じ発行年内で次のように号数の昇順になる。

```text
2026年1月号
2026年2月号
2026年6月号
2026年7月号
2026年8月号
2026年9月号
2026年10月号
```

## 確認結果

- `git diff --check`：問題なし。
- URL生成、許可値検証、ORDER BY、上下ページネーションのパラメータ維持を差分上で確認した。
- このローカル環境には PHP CLI がないため、`php -l` は実行できなかった。
- デフォルトURLの「号 ▲」表示、実データの号数順、各ヘッダーの昇順・降順、ページ移動後の条件維持はテスト環境で要確認。

## 備考

- DBスキーマおよび登録データは変更していない。
- 実データを使う表示確認は、テスト環境へアップロード後に行う。
