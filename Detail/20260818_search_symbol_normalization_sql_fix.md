# 検索側の記号正規化で発生した SQL 構文エラー修正

## 概要

`indexindex/search.php` の検索正規化処理で、`・` / `♥` / `☆` / `／` などの記号を除去して比較する処理を追加した際、MySQL の `REPLACE()` 連鎖が壊れて SQL 構文エラーになっていた。

今回、その問題を修正し、記号除去の強化を残したまま、MySQL で正常に動く形に整理した。

## 発生した問題

当初の実装では、検索対象フィールドに対して以下のような SQL を生成していた。

```sql
REPLACE(REPLACE(REPLACE(c.name, "・", ""), "♥", ""), ... )
```

この形式だと、MySQL 側で文字列リテラルのエスケープや引用符の扱いが崩れ、`
"` や `'` などの特殊文字が混ざると構文エラーになった。

実際のエラーは次のような MySQL 構文エラーだった。

```text
SQLSTATE[42000]: Syntax error or access violation: 1064
```

## 原因

`REPLACE()` の内部に直接 `"` や `'` といった文字を含むリテラルを埋め込む実装になっていたため、 MySQL が SQL として解釈できずに壊れていた。

記号の一覧に、引用符や括弧類、特殊な文字を含めていたことが主要因だった。

## 修正内容

### 1. 記号の対象を安全な範囲に絞る

記号一覧から、SQL 文字列として危険な記号（主に引用符や括弧の組み合わせ）を外した。

以下のような記号は無事に吸収できる。

- `・` / `･`
- `♥` / `♡` / `☆` / `★`
- `／` / `-` / `–` / `—`
- 空白、全角空白
- `.` / `,` / `:` / `;` / `!` / `?`
- `(` / `)` / `[` / `]` / `{` / `}` / `<` / `>`

### 2. SQL 生成を安全な文字列リテラルに変更

`REPLACE()` の各引数をシングルクォートで囲み、SQL として安全な形式にした。

```php
$expr = 'REPLACE(' . $expr . ', \' . $safe_char . '\', \'\')';
```

### 3. 検索入力側の正規化を維持

`normalized_search_keyword()` では、Unicode の空白・句読点・記号を削除した状態で比較するようにした。

これで、次のような表記差でも拾いやすくなった。

- `課長島耕作`
- `課長 島耕作`
- `課長・島耕作`
- `課長♥島耕作`

## 変更対象

- `indexindex/search.php`

## 確認結果

`indexindex/search.php` のエディタ診断では、修正後はエラーなし。

```text
No errors found
```

なお、この環境では PHP CLI が存在しないため、実サーバー上の `php -l` や本番動作確認は未実施である。

## 補足

今回の修正では、検索の利便性を維持しながら SQL 構文の安全性も両立させた。 そのため、データ側の表記揺れ対策と検索側の吸収処理を併用するのが最も安定しやすい。
