# 検索側の記号表記ゆれ吸収の拡張

## 概要

`indexindex/search.php` で、これまで `・` / `･` のような日本語の中点を除去して比較していた処理を、より一般的な記号表記ゆれにも対応させた。

これにより、次のような差異でも検索結果として同一視できるようになった。

- `課長・島耕作`
- `課長･島耕作`
- `課長♥島耕作`
- `課長☆島耕作`
- `課長/島耕作`
- `課長-島耕作`

## 背景

作品名や作者名では、句読点や装飾記号が入ることがある。 特に編集時の表記揺れにより、以下の差が起こりやすい。

- `・` と `･`
- `♥` / `♡` / `★` / `☆`
- `／` / `-` / `–` / `—`
- 空白や括弧類の有無

このままだと、入力文字列に記号が含まれているだけで検索が漏れやすくなっていた。

## 修正内容

### 1. 記号の吸収対象を一般化

`search.php` の `normalized_search_sql()` と `normalized_search_keyword()` を見直し、次のような記号を削除して比較するようにした。

- 空白類
- 中点類
- 日本語の句読点類
- 装飾記号類
- 記号類（`/`, `-`, `–`, `—`, `+`, `=`, `@`, `#`, `$` など）

### 2. SQL側でも対応

`normalized_search_sql()` は、対象フィールドから候補の記号を順次 `REPLACE()` して、見た目上の差分を取り除く処理にした。

### 3. 入力値側でも対応

`normalized_search_keyword()` は、検索入力文字列から Unicode の空白、句読点、記号、装飾記号を一括で除去するようにした。

これにより、記号やスペースの差異で検索が落ちることが減る。

## 期待される挙動

以下の検索入力で、同一語として扱えるようになった。

- `課長島耕作`
- `課長 島耕作`
- `課長・島耕作`
- `課長♥島耕作`
- `課長☆島耕作`

## 変更対象

- `indexindex/search.php`

## 確認結果

`indexindex/search.php` の診断確認を実施し、編集後もエラーは出ていない。

```text
No errors found
```

なお、この環境では PHP CLI は利用できないため、実DBでの実運用確認は未実施である。

## 補足

今後は、データ側に「正規化表記」を持たせる方法と、検索側の「吸収処理」を併用すると、より安定した表記ゆれ対策になる。 ただし、記号の削除が広すぎると意図しない語の重なりが出ることもあるので、必要に応じて対象記号を絞る調整もできる。
