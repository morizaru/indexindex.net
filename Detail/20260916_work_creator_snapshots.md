# 作品人物から掲載人物へのスナップショット登録

## 調査

- `admin/content_add.php`: タイトルの完全一致で作品を取得し、なければ作品を作成。目次INSERT後に入力人物を登録していた。
- `admin/content_bulk_add.php`: 選択作品IDとタイトルを検証し、該当しなければタイトルで取得・新規作成。各目次INSERT後に入力人物を全員表示ONで登録していた。過去の掲載から人物名のみを自動補完する処理があった。
- `admin/content_edit.php`: 保存ごとにタイトルから作品を決定。既存人物を全削除しフォームから再登録していたため、掲載時の表示名・所属を失う構造だった。
- `admin/content_suggest.php`: 一括登録で使う作品・人物候補取得。今回は変更なし。
- `admin/work_edit.php`: 作品情報の編集画面。人物管理は未対応。作品名保存時に掲載タイトルを同期する既存処理あり。今回は変更なし。
- `admin/works.php`: 掲載ゼロ作品の一覧・編集導線あり。今回は変更なし。
- `AGENTS.md`、`app/`、`includes/`: 共通の人物保存ヘルパーはなく、画面ごとに関数が定義されていた。`app/config.php` はローカルに存在せず、変更していない。

単体登録・編集では人物名、別名の順に検索し、見つからなければ人物を新規作成する。一括登録の既存処理は人物名のみで検索・作成し、役割名も検索・必要に応じて作成する。作品新規作成時に人物を作品側へ逆登録する処理は追加していない。

## 確認済みのDB情報

ユーザー提供の7テーブルの列構成とインデックスを使用した。`work_creators` のUNIQUEは `(work_id, creator_id, role)`。`content_creators` には人物・役割のUNIQUEはない。役割列の照合順序は両方とも `utf8mb4_general_ci`。対象テーブルからの外部キー検索は0件、トリガーは0件との回答を受けた。DDL変更はない。

## 変更ファイルと挙動

### app/content_creators.php（追加）

`ContentCreatorWriter` に共通処理を配置。プリペアドステートメントをインスタンス内で再利用する。

- `syncWorkCreatorsToContentCreators`: `INSERT ... SELECT ... NOT EXISTS` で全人物を一括コピー。creator_id、role_id、role、display_order、default_visible → is_visible をそのままコピーする。空欄のrole、NULLのrole_idも保持する。
- 重複判定は `content_id + creator_id + role`。文字列比較はDBの照合順序に従い、role_idが異なっても同じ人物・roleは追加しない。
- コピー先の既存行は上書きしない。表示名・所属の新規行はDB既定値のNULL。
- `insertIfMissing`: 手入力にも同じ重複チェックを適用。
- 新規目次はINSERTのトランザクションが親行のロックを保持する。編集は親目次行を明示的にロックする。対象3画面からの保存を直列化するが、同じ規約を使わない外部SQLの重複までは防げない。

### admin/content_add.php

目次INSERT直後、同じトランザクションで作品の人物をコピー。その後で手入力人物の不足分だけ追加する。コピー済み人物の表示設定・表示順は手入力で上書きしない。手入力人物のrole_idは役割名から検索し、hidden値を信用しない。未登録の役割名はrole_idをNULLにして保存する。

### admin/content_bulk_add.php

各目次INSERT直後に同じコピー処理を実行。人物ごとにコピー元をSELECTせず、目次1件につきコピーSQLを1回実行する。共通ステートメントは一括登録全体で再利用する。

作者入力が空でも、作品から人物をコピーできれば登録可能。作品側にも人物がなく手入力もなければ、従来どおり登録を拒否し、一括登録全体をロールバックする。

旧自動補完は作品マスターからの人物案内に変更。人物名を入力欄へ転記しないことで、役割の欠落や表示初期値の上書きを防ぐ。案内は選択作品IDまたはタイトル完全一致で取得する。同名作品が複数ある場合、未選択状態では案内を表示しない。

### admin/content_edit.php

- 保存ごとに全削除する方式を廃止。既存行はIDを維持してUPDATEする。
- `display_name` と `display_affiliation` を更新対象に含めず、掲載時の情報を保持する。
- フォームで削除した行、または人物名を空にした行のみ削除する。
- 既存人物名が未変更なら元のcreator_idを維持する。役割が未変更なら元のrole_idを維持し、変更時は役割名から再取得する。
- 既存行の空欄role、全角表記、表示順0などを保存だけで変換しない。
- 既存重複は一括整理しない。新規追加は不足分のみ。人物・役割変更で重複が生じる場合はエラーにする。
- 編集開始後に人物情報が変わっていた場合は、再読み込みを求めて保存を拒否する。
- work_idが変わっても既存人物は保持し、自動展開しない。「保存時に作品の人物を不足分だけ追加する」を選んだ場合のみ、新しい作品の不足人物を追加する。既存の非表示設定は上書きしない。

## 既存データへの影響と未実装

既存データの一括削除・再生成・一括補完は行わない。公開ページも変更せず、掲載側の人物情報を引き続き参照する。作品側の変更は過去の掲載人物に伝播しない。

作品単体の人物登録画面は未実装。既存の `admin/work_edit.php` に人物欄を追加するのが自然。作品自体を未掲載状態で新規作成するには、`admin/works.php` から作品追加画面への導線を設ける案。

目次から作品への逆登録、掲載時の表示名・所属の入力UI、公開ページのリアルタイム作品人物参照、既存人物の重複整理は未実装。
