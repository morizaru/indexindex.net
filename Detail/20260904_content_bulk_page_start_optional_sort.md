# 2026-09-04 一括登録 開始ページ任意化と掲載順再採番修正

## 対象

- `indexindex/admin/content_bulk_add.php`

## 指摘内容

- `content_bulk_add.php?issue_id=18876` の一括登録で、開始ページ部分が勝手に必須化されていた。
- 開始ページが分からない目次もあるため、開始ページなしでも登録できる必要がある。
- 並び順は以下にしたい。
  - 開始ページあり/なしが混在する場合: 開始ページ順 + No順
  - 全て開始ページが入っていない場合: No順

## 原因

- 前回修正で `開始ページを入力してください。` のバリデーションを追加してしまっていた。
- 登録時の `sort_order` が一律 `999999` で、開始ページなし行の入力No順を保持できない状態だった。
- 再採番処理は開始ページ優先で、開始ページがない場合のNo順保持が弱かった。

## 修正内容

- 開始ページ必須バリデーションを削除。
- 開始ページが入力されている場合だけ、従来どおり半角数字チェックを行う。
- 登録時の仮 `sort_order` に、一括登録フォーム上の入力Noを保存するよう変更。
- `renumber_issue_contents()` の再採番順を変更。
  - 対象雑誌号に開始ページが1件もない場合: `sort_order ASC, id ASC`
  - 開始ページあり/なしが混在または一部ありの場合: `page_start` ありを開始ページ順、同一ページやページなしは `sort_order ASC, id ASC`

## DB変更

なし。

- `git diff --check -- indexindex/admin/content_bulk_add.php`: エラーなし

## 未確認事項

- 本番/テスト環境で、開始ページなし行を含む登録後の掲載順を確認する必要あり。

## 確認手順

1. 全行の開始ページを空にして数件登録し、No順で掲載順が付くことを確認する。
2. 開始ページあり/なしを混ぜて登録し、ページありは開始ページ順、ページなしは入力No順で後ろに並ぶことを確認する。
3. 開始ページが空でも、タイトル・作者があれば登録できることを確認する。
4. 開始ページに数字以外を入れた場合は、従来どおりエラーになることを確認する。
